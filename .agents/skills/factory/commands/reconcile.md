`/factory reconcile [--dry-run]`: clear stuck cards with a maintainer. It has five rules, and each card gets at most one action, from the first rule that fires:

- `unblock-when-blockers-closed`: take the `blocked` label off an open card in Backlog (or with no Status) once every issue blocking it is closed.
- `clear-stale-stop`: take a leftover `factory:stop` label off a closed issue, in any column, Done included.
- `orphaned-run`: move an open card in **Build** or **Review** whose issue holds no run slot on origin (no `refs/factory/slots/<k>`, the slot a live run holds from Spec through Review) to **Needs human**, and take `factory:stop` off it too when it has one.
- `triage-untriaged-insider`: list an open issue that nobody has triaged yet (no card on the board, no finding label, no `needs-info`) when an insider filed it, so you triage it with a person in step 4. The script only prints the line: it writes nothing for it.
- `split-needs-split` (action `propose-split`): propose how to split an open card in Backlog (or with no Status) that's labelled `needs-split` and has no sub-issues, and record the proposal on the card as a comment. It files nothing: `/factory groom` files the parts.

Like [Groom](#groom), this does no run work: no branch, no run records and no agents. Reconcile never merges or closes an issue and never adds a label. Its only move is to Needs human, by setting the card's Status: it posts no `🏭` transition comment and doesn't touch the progress checklist. The triage decisions in step 4 aren't reconcile's: `node $B triage` makes them, with triage's own writes (it can close an issue, set labels and move an accepted one to Backlog), and only once a person confirms each one.

1. **Run the dry-run first**, always: `node $B reconcile --dry-run`. It reads the open issues on the board and off it, and the closed ones labelled `factory:stop`, plus the run slots on origin when a Build or Review card needs them, and the comments on each `needs-split` card the split rule may act on. It writes nothing: no label change, no Status change, no comment and no log entry. It prints one line per card a rule is about:
   - `` → #<n> unblock-when-blockers-closed: #<a> CLOSED, #<b> MERGED → unblock (remove the `blocked` label) ``: the card, the rule, the evidence (each dependency and its state) and the action. A card's dependencies are its GitHub "blocked by" issues plus the refs on its `Depends on:` lines (an external card's `Depends on:` lines are ignored).
   - `` → #<n> clear-stale-stop: #<n> CLOSED → clear-stop (remove the `factory:stop` label) ``: a closed issue that still has `factory:stop`.
   - `→ #<n> orphaned-run: no run slot held for #<n> → needs-human (move <column> → Needs human)`: a Build or Review card no run holds. When the card has `factory:stop`, the line ends `` and remove the `factory:stop` label) ``.
   - `→ #<n> triage-untriaged-insider: @<author> insider, off the board → triage (decide with /factory triage)`: an insider's untriaged issue, for step 4.
   - `→ #<n> split-needs-split: #<n> est <lines>, <count> behaviours → propose-split (propose a split into <k> parts)`: the card's size block gives the estimate and the behaviours. The parts take the behaviours in order, as few parts as can each hold at most 4 behaviours with an even share of the estimate at or under `settings.size_limit`.
   - `- #<n> skipped: <reason>`: reconcile leaves the card alone. The reason is a dependency that's still open (`waits on #<a>`), no dependencies at all (a `blocked` card with none is a person's gate), a dependency that can't be read, a run slot the issue holds (`holds run slot <k> (<session>, since <time>)`), run slots that can't be read (`run slots can't be read: <error>`, on every Build and Review card; a slot whose holder can't be read counts, as `run slot <k> holder unknown`), an opt-out label (`labelled factory:manual`, `human-task` or `external`, under every rule; on a closed issue it adds `(closed, factory:stop left on)`), a `blocked` or `needs-split` card in Spec, Ready, Approve or Needs human (`in <column>`), an untriaged issue from an external author (`external filer (use /factory triage)`: it waits for `/factory triage`, never for reconcile), a `needs-split` card that already has the proposal comment from an insider (`split already proposed`), one with no size block or no behaviours in it (`no behaviours in its size block; size it at /factory groom`), one whose estimate is at or under `settings.size_limit`, so it fits in one part (`fits in one part (est <lines>, limit <limit>); check its needs-split label at /factory groom`), one with a single behaviour and an estimate over the limit (`one behaviour; split it by hand at /factory groom`), or one whose comments can't be read (`its comments can't be read: <error>`). A `needs-split` card that has sub-issues is left out: it's already split.
   - `nothing to reconcile`, last, when no card has an action.

   The plan's bracketed text says what apply would do; the comments and the `✓` lines apply prints say what it did.
2. **Show the plan to the maintainer and wait for a yes.** Apply it only after a person confirms it; there is no automatic reconcile. If they want a card left alone, don't apply: tell them to add `factory:manual` to it (or remove its dependency link), then run the dry-run again. The repo may not have that label yet: create it first with `gh label create factory:manual`. Or leave the card's number out of `--only` in step 3. A run slot that's still held but stale (an old `since`, a gone checkout) keeps its card out of `orphaned-run`: a person frees it with `node $B slots free <k>` first.
3. **Apply** the confirmed plan: `node $B reconcile --only <confirmed numbers>`, the numbers comma-separated (for example `--only 12,15`), so it acts only on the cards the maintainer said yes to. Don't run two applies at once, in this session or another: each acts on what it reads, and their writes can cross. It reads the board and the slots again and, for each card with an action:
   - A card with an action that isn't in `--only` is skipped with `- #<n> skipped: not in the confirmed plan`, and nothing is written for it.
   - `unblock` and `clear-stop` first read the card's labels again, and skip it with `` - #<n> skipped: changed since the plan: <label> already removed `` when the label is already gone (no comment, no log entry); otherwise `unblock` removes `blocked` and `clear-stop` removes `factory:stop`; `needs-human` first reads the card's Status and the slots once more, and skips the card with `- #<n> skipped: changed since the plan: …` when it left its column or its issue now holds a slot. Otherwise it removes `factory:stop` when the card has it, then sets the card's Status to Needs human.
   - Then it posts a comment whose first line is `<!-- factory:decision -->`, with the rule, the evidence, what changed, and the undo: re-add `blocked` or `factory:stop` (`gh issue edit <n> --repo <owner>/<repo> --add-label <label>`), or set its Status back to the column it came from on the board (and re-add `factory:stop` when it was removed). A needs-human comment also gives the next step: `` `/factory revise <n> "<instructions>"` to resume the run, or `/factory reject <n> "<reason>"` ``.
   - `propose-split` makes no label, Status or issue change: it first reads the card's comments again, and skips it with `- #<n> skipped: changed since the plan: split already proposed` when an insider posted a proposal since the plan. Otherwise it only posts the comment, titled `### 🏭 Reconcile: propose-split`, which lists each part with its behaviours (any `<!--`, `-->` or `--!>` in them escaped) and its estimated code lines, and says that `/factory groom` files the parts. Its undo is to delete the comment.
   - Then it appends one `reconcile` entry to the audit log, and prints `✓ #<n>: reconcile <action> (<rule>)`.
   - A `triage-untriaged-insider` line gets no write, no comment and no log entry.

   It prints the plan again from what it reads now, so if a card changed since the dry-run, its plan differs: show the maintainer any difference. `--only` keeps it from acting on a card nobody confirmed.
4. **Triage the insider issues**, one at a time, for each `triage-untriaged-insider` line: first read the issue and its `missing` sections (`gh issue view <n> --json title,body,author,comments`, and its item under `requests` in `node $B intake --json`, which prints `{ requests, epics }`; reconcile never lists an `epic`, which triage gives a milestone only), as [Triage](#triage) step 2 does. Then propose one of the `triage` decisions (`accept`, `duplicate`, `reject` or `needs-info`) with its summary text and, for an `accept`, its milestone, as Triage steps 3 to 5 do, and get a person's yes for each. Then record it with `node $B triage <n> <decision> [--into <x>] [--milestone M] --summary-file $S`, as Triage step 6 does, which posts triage's own comment, sets its labels and milestone and logs it, and size each accepted issue as Triage step 7 does. Never triage without a yes. Never triage an issue from a `skipped: external filer` line here: those go through `/factory triage`, with its restatement.
5. A failed write prints `⚠️ #<n>: …` with the problem, logs the entry with `verified: false`, goes on to the next card, and exits `1` at the end. The problem says what's still true and names any write in the step that already succeeded (for example `status: …; #<n> is still in Review, but factory:stop was removed, so no comment was posted`). Show each `⚠️` line to the maintainer.
   - A failed label removal or Status change posts no comment and makes no later write for that card. A card whose `blocked` or `factory:stop` is still on, or that is still in Build or Review with no slot, is planned again by the next reconcile: run it again once the cause is fixed.
   - A failed comment (or log write) leaves the change made but unexplained on the issue: the `⚠️` line and the log entry hold the evidence and the undo. Post them on the issue by hand, or undo the change as the line says.
   - A failed re-check before a label removal, a needs-human move or a split comment (`⚠️ #<n>: skipped: can't re-check it before the label removal: …`, `… before the move: …` or `… before the comment: …`) changes nothing; run reconcile again.
   - A failed `propose-split` comment changes nothing either, since the comment is its only write: run reconcile again to post it.
6. Print a summary: each card changed (with its evidence), each issue triaged and its decision, each card skipped and why, and any `⚠️` problems. Then stop.
