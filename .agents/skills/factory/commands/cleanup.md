`/factory cleanup`: remove the leftover `factory/*` worktrees and branches of Done cards, once a person confirms.

Like [Reconcile](#reconcile), this does no run work: it creates no worktree, moves no card, writes no record, spawns no agent and claims no run slot. It runs only from the primary checkout (the first entry of `git worktree list`), never from a session's linked worktree.

1. **Dry run.** From the primary checkout, run `node $B cleanup`. It fetches, prunes and lists every leftover worktree and branch as `- remove …` or `= keep …`, each with why, then `<r> to remove, <k> to keep (dry run: nothing was changed)`. Show the person that whole list, and any `! no issue could be read; check gh auth status` line (every issue read failed, so every card was kept; fix `gh` first). If it exits `2` (not the primary checkout), tell the person to run `/factory cleanup` from the primary checkout and stop. If it exits `1`, show its `✗` line and stop. If nothing is to remove, say so and stop.
2. **Confirm.** Ask the person whether to remove the items marked `remove`. Without a clear yes, stop: nothing has changed.
3. **Apply.** Only after the person confirms, run `node $B cleanup --apply` from the same checkout. It fetches and classifies again, then removes whatever is `remove` at that moment (each clean worktree, never with `--force`, then the local branches and the origin branches, each guarded by the tip it read) and leaves every `keep` item alone, so it can remove an item the person didn't see. Compare its `- remove` lines with the list the person confirmed, and point out any `- remove` line that wasn't in it. Show its `✓ removed …` and `✗ failed …` lines and its `<r> removed, <f> failed, <k> kept` summary. If it prints only a `✗ fetch failed` or `✗ worktree prune failed` line, show it and say nothing was removed. On any other exit `1`, name each failed item and git's reason; a later `/factory cleanup` lists it again.
