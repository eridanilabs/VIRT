`/factory approve <n>`: a person has looked at the PR and says ship it. `<n>` may be the **issue or the PR** number.

1. Resolve it. If `gh pr view <n> --json number,headRefName` succeeds and `headRefName` matches `factory/<issue>-*`, that's the PR and the issue. Otherwise treat `<n>` as the issue and find the open PR whose `headRefName` starts with `factory/<n>-`. If neither works, stop and say so. Then read `gh pr view <p> --json isCrossRepository,headRefName,state` for that PR and refuse, stopping with the reason, if `state` isn't `OPEN` (`PR isn't open`: a stale PR number must never reach [Merge](#merge)), if `isCrossRepository` is true (`PR is from a fork`), or if `headRefName` doesn't match `^factory/<issue>-[a-z0-9]+(-[a-z0-9]+)*$` (`branch name not allowed`): the name goes into git commands from step 3 on, and [Merge](#merge)'s `node $P merge` refuses either anyway.
2. The card must be in `Needs human`. Check with `node $B status`. If it's elsewhere, stop and say where, ending with the [`factory-result`](#the-factory-result-line) line, outcome `refused`. Don't approve a PR that's already in the merge queue: an earlier `/factory approve` is still waiting for it to merge, and the card stays in Needs human for up to 60 minutes while it does. Wait for that run to finish, as for a `merge queue timed out`.
3. [Find the run's checkout](#finding-a-runs-checkout) with the PR's `headRefName` as `<branch>` and work in the checkout it returns: the session's own worktree, as `workspace <n> --continue` decided, with no `gh pr checkout`. Build the run's [pinned copy](#the-runs-pinned-loop) there: Merge's gates run from it. Record `Approved by @<gh user> on <date> via /factory approve.` as `approval-human`.
4. [Merge](#merge) from `Needs human`, with reason `approved by @<gh user>`. Merge's CI check (step 2) still applies: the approval doesn't skip a failing or missing check.
